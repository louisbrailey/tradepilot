# Windows network status publisher

Tailscale 1.102.4's Windows LocalAPI admits the active profile owner or LocalSystem, and its pipe grants Builtin Users/System access. The restricted gateway account must not acquire that broad authority. `TradePilotNetworkStatus` is a separate, fixed-purpose LocalSystem service. Gateway and Ollama retain their existing virtual accounts.

The publisher imports no gateway, broker, market environment, pairing or ledger modules. The common SCM module imports only service/runtime primitives; gateway imports occur only inside the gateway service path. The publisher clears inherited environment and executes only `C:\Program Files\Tailscale\tailscale.exe status --json --peers=false`. Its executable and parent require ordinary paths, administrator ownership, and no other writers. There is no arbitrary command, path, listener or request API. The service has its own 256 MiB kill-on-close job (including children), an 8-second query deadline, 128 KiB retained stdout ceiling, discarded stderr, and stop-driven child termination. The output reader drains with a bounded join. Publication normally runs every five seconds; failure immediately publishes unavailable status.

`C:\ProgramData\TradePilotNetworkStatus` is an Admin/System-owned control directory. Only those principals may write; the gateway gets read/execute. Each atomic status file is explicitly System-owned, Admin/System writable, and gateway-readable. Temporary files never include the raw Tailscale response. The exact receipt contains schema version, success, BackendState, SelfOnline, IPv4, DNSName, UTC timestamp, kernel boot GUID, and GetTickCount64 uptime. No peer/user/profile details are persisted. Status files are at most 4096 bytes.

Consumers pin the control directory against deletion and pin the receipt file against writes/deletion, check owner/DACL and ordinary unaliased file identity, reject unknown ACE kinds, bound reads and reject duplicate JSON keys. Directory handles allow write sharing for child-file creation/rename; their DACL permits only administrator writers. They require the same kernel boot GUID, UTC and uptime ages both between zero and 20 seconds, and agreement within two seconds. Clock jumps, stale/previous-boot receipts, query failures, malformed values, missing files and untrusted writers fail closed. This is a publication-age bound; a query itself may have taken up to eight seconds. The gateway retains its existing online/address/exact MagicDNS comparison before starting and during operation. Synthetic preflight checks expected address, online state and a valid nonempty MagicDNS name without reading production configuration.

## Installation and accepted startup

Fresh `Install-Candidate.ps1` still refuses any existing deployment. It registers all three services DISABLED. Only the publisher uses LocalSystem (the SCM default for that explicit new service); the other accounts stay restricted. Publisher depends on Tailscale; gateway depends on Tailscale, publisher and Ollama. Neither installation path starts a service.

`Configure-AcceptedStartup.ps1` remains gated on independent acceptance and the Mac writer fence. All three services must be stopped. It configures delayed startup, dependencies, and three restart actions followed by SC_ACTION_NONE, with a one-day reset period. It does not start services. Parent-owned service-identity acceptance and logout/reboot verification are still required. Tailscale unattended mode remains a separately reviewed parent setting, not a publisher permission workaround.

## Existing 724697e deployment delta

The owner executes the reviewed `Update-NetworkStatus.ps1` from verified Admin-only staging with a protected approval receipt containing decision ALLOW, mode network-status-delta, base_manifest_sha256, manifest_sha256, and delta_sha256. The base manifest hash is fixed to `3a0bfe014e6582c30358ebf407efe474307ac3ba570cd318dac889a6bb29e724` (724697ec708bdce9a71102facc3eca86b5019d07). The target manifest's own delta entry must match the approved delta hash. Parent must verify the bytes actually executed; the script does not manufacture its own trust.

Both existing services must already be stopped and disabled, use the expected virtual accounts, and point at the existing protected pythonservice host. The delta rejects an activation permit or any existing publisher/control root. It verifies every old payload file and every target file; its pure manifest planner rejects removals and any change outside the enumerated network deployment files. No runtime, wheel, backend, model, frozen algorithm or private state changes are allowed.

Changed bytes are copied and rehashed in a new Admin-only `Program Files\TradePilot\reviewed-updates\<target-manifest-hash>` directory. Original changed files, original and target manifest bytes, and prior service/dependency metadata are preserved there. Files are replaced individually while services remain disabled; this is not an atomic whole-install transaction. New source files receive the standard protected code ACL. Only the new publisher is registered; its identity/start mode is verified. The new control root is created, dependencies updated, and installed manifest receipt replaced last. Existing gateway private state, control requests, backups and cutover receipts are never copied, read or overwritten (only activation-permit existence is checked).

Failure leaves stopped/disabled services and retained update evidence for owner inspection; there is no automatic retry, destructive rollback, service start or ledger operation. Re-running with the same staging directory or a newly registered publisher fails closed. Recovery requires the owner to inspect the saved before-files/manifests/dependency metadata and separately review restoration. Do not rerun the fresh installer or delete the existing installation.
